# 물리 관절형 로봇 전환 전 기준 상태

이 문서는 `물리_관절형_로봇_전환_설계서.md`의 **단계 0: 기준 상태 기록** 결과입니다.
물리 관절형 로봇으로 전환한 뒤에도 같은 장면과 같은 입력을 사용해 결과를 비교합니다.

## 1. 기준 버전

- 기록 날짜: 2026-08-13
- Unity: 6000.3.8f1
- 기준 브랜치: `Physical-Articulated-Robot`
- 기준 커밋: `71c0982b` (`Feat: 발 접촉 기반 지면 반력과 무게중심 균형으로 이동 로직 개선`)
- 기준 장면: `Assets/Scenes/3MainScene.unity`
- 로봇 생성 위치: 월드 좌표 `(-11, 4, 0)`
- Unity 2D 물리 계산 간격: `0.02초` (초당 50회)
- Fusion 틱 설정: `NetworkProjectConfig.fusion`의 기본값 선택(`TickRateSelection`의 모든 값이 0)

이 게임은 **4인 협동 게임**입니다. 네 플레이어는 각각 왼쪽 팔, 왼쪽 다리, 오른쪽 팔, 오른쪽 다리 하나만 담당합니다. 아래의 모든 플레이 검증은 네 역할이 모두 배정된 4인 방을 기준으로 합니다.

현재 `UIManager.OnPlayButtonPressed()`가 입장 순서에 따라 `InputAuthority`를 연결하는 실제 순서는 왼쪽 다리, 오른쪽 다리, 왼쪽 팔, 오른쪽 팔입니다. 이것은 현재 코드 상태를 재현하기 위한 기록이며, 게임의 역할을 설명하는 순서와는 구분합니다.

기준 커밋에는 현재 로봇 동작을 만드는 다음 프리팹과 스크립트 변경이 함께 보존되어 있습니다.

- `Assets/Resources/Prefabs/Robot.prefab`
- `Assets/Resources/Prefabs/Left Leg IK.prefab`
- `Assets/Resources/Prefabs/Right Leg IK.prefab`
- `Assets/Scripts/LegTest/BodyController.cs`
- `Assets/Scripts/LegTest/LegManager.cs`

팔 동작과 몸통 기울기 기준은 바로 앞 커밋 `da1a0a62`에 보존되어 있으며, 기준 커밋 `71c0982b`에도 그대로 포함되어 있습니다.

## 2. 현재 물리 구조

| 대상 | Rigidbody2D | Collider2D | HingeJoint2D | 현재 움직이는 방식 |
|---|---:|---:|---:|---|
| 몸통 | 1개 | Capsule 1개 | 0개 | 실제 2D 물리 |
| 왼쪽 다리 | 0개 | 0개 | 0개 | Transform 기반 2-bone IK |
| 오른쪽 다리 | 0개 | 0개 | 0개 | Transform 기반 2-bone IK |
| 왼쪽 팔 | 손에 Kinematic 1개 | 손에 Circle 1개 | 0개 | Transform 기반 2-bone IK |
| 오른쪽 팔 | 손에 Kinematic 1개 | 손에 Circle 1개 | 0개 | Transform 기반 2-bone IK |

현재 로봇에서 질량과 중력의 영향을 실제로 받는 부품은 몸통 하나뿐입니다. 다리에는 Rigidbody2D와 Collider2D가 없으며, 팔의 손 Rigidbody2D는 Kinematic이라서 팔의 질량이나 반작용을 몸통에 전달하지 않습니다.

| 항목 | 기준값 | 값이 저장된 곳 |

## 4. 전환 전 문제 재현 절차

### 4.1 공통 준비

1. `Assets/Scenes/3MainScene.unity`를 엽니다.
2. Unity에서 Play를 누릅니다.
3. 네 명의 플레이어가 방에 모두 들어옵니다.
4. 호스트가 Play 버튼을 눌러 로봇을 생성합니다.
5. 각 플레이어가 자신에게 배정된 왼쪽 팔, 왼쪽 다리, 오른쪽 팔, 오른쪽 다리만 움직이는지 확인합니다.
6. 현재 코드에서는 입장 순서대로 왼쪽 다리, 오른쪽 다리, 왼쪽 팔, 오른쪽 팔이 배정됩니다.
7. 다시 시작할 때는 호스트 창에서 `R`을 눌러 몸통의 위치, 회전, 속도를 초기화합니다.

여러 창을 한 사람이 번갈아 선택하는 방식은 4인 검증으로 인정하지 않습니다. 현재 선택한 창 하나만 새 마우스 위치를 받기 때문에 네 역할의 입력 시점과 협동 결과를 정확히 확인할 수 없습니다. 네 사람이 각자 자신의 게임 창을 조작하거나, 네 역할에 서로 다른 입력을 같은 틱에 넣는 자동 입력 도구를 사용해야 합니다.

### 4.2 문제 A: 다리를 공중에서 움직여도 몸통에 반작용이 없음

필요 인원: 4명. 왼쪽 다리 담당자가 주 입력을 하고 나머지 세 명은 사지를 중립 위치에 둡니다.

1. 로봇이 떨어지는 중이거나 발이 바닥에서 떨어진 상태를 만듭니다.
2. 왼쪽 다리 담당 창에서 마우스를 화면 왼쪽 끝과 오른쪽 끝으로 빠르게 반복 이동합니다.
3. 몸통의 움직임과 회전을 관찰합니다.

전환 전 기준 결과:

- 발과 무릎은 Transform으로 움직입니다.
- 다리에는 질량과 관절이 없으므로 다리 움직임 자체의 반작용은 몸통에 전달되지 않습니다.
- 발이 땅에 고정된 경우에만 `BodyController`의 별도 지면 반력 계산이 몸통에 힘을 줍니다.

전환 후 비교 기준:

- 공중에서 다리를 움직이면 실제 다리 질량의 반작용만큼 몸통 자세가 변해야 합니다.
- 발이 바닥에 닿지 않았다면 몸통이 계속 위로 올라가는 힘은 생기면 안 됩니다.

### 4.3 문제 B: 발의 힘이 아니라 별도 계산이 몸통을 일으킴

필요 인원: 4명. 양쪽 다리 담당자가 함께 입력하고 양쪽 팔 담당자는 균형을 방해하지 않는 중립 위치를 유지합니다.

1. 양발을 바닥에 고정합니다.
2. 두 다리 담당자가 마우스를 각 발보다 아래로 내립니다.
3. 몸통이 위로 올라가는 동안 발, 무릎, 몸통의 움직임을 관찰합니다.

전환 전 기준 결과:

- `LegManager.TryGetStandingSupport()`가 상승 가능 거리와 입력 세기를 계산합니다.
- `BodyController.ApplyGroundReactionPhysics()`가 계산한 힘을 몸통 Rigidbody2D에 직접 적용합니다.
- 발과 무릎은 실제 관절이 아니므로 지면의 힘이 관절을 따라 몸통으로 전달되는 과정은 없습니다.

전환 후 비교 기준:

- 별도의 몸통 상승 계산 없이 발 Collider의 반작용이 발목, 무릎, 골반 관절을 거쳐 몸통에 전달되어야 합니다.

### 4.4 문제 C: 팔의 질량 대신 별도 토크가 몸통을 기울임

필요 인원: 4명. 양쪽 다리 담당자는 로봇이 설 수 있게 발을 유지하고, 양쪽 팔 담당자가 비교 입력을 수행합니다.

1. 로봇을 평지에 세웁니다.
2. 왼팔 또는 오른팔 담당자가 팔을 한쪽으로 길게 뻗습니다.
3. 팔을 반대쪽으로 옮긴 뒤 몸통 기울기 변화를 관찰합니다.
4. 양팔 담당자가 두 팔을 같은 방향과 반대 방향으로 각각 뻗어 비교합니다.

전환 전 기준 결과:

- 팔 부품의 질량이 몸통을 당기는 것이 아닙니다.
- `ArmManager.GetTorsoLeanRequest()`가 `-1~1` 값을 만들고, `BodyController.ApplyArmDrivenLean()`가 몸통에 별도 토크를 적용합니다.
- 같은 방향의 양팔 입력은 더해지고 반대 방향 입력은 서로 줄어듭니다.

전환 후 비교 기준:

- 별도 몸통 기울기 토크 없이 실제 팔의 질량, 관절 모터, 반작용만으로 몸통이 기울어야 합니다.

### 4.5 문제 D: 손과 발 목표가 입력 직후가 아니라 정해진 속도로 이동함

필요 인원: 4명. 네 담당자가 같은 절차를 자신의 사지에 한 번씩 수행합니다.

1. 왼쪽 팔, 왼쪽 다리, 오른쪽 팔, 오른쪽 다리 순서로 한 역할씩 검사합니다.
2. 검사할 사지의 손 또는 발 근처에 담당자의 마우스를 둡니다.
3. 담당자가 마우스를 화면 반대쪽으로 한 번에 빠르게 옮깁니다.
4. 마우스가 멈춘 뒤 손 또는 발이 목표점에 도달할 때까지의 움직임을 관찰합니다.
5. 검사하지 않는 세 담당자는 자신의 사지를 중립 위치에 유지합니다.

전환 전 기준 결과:

- 발은 `footSpeed = 15`, 손은 `handSpeed = 15`의 속도로 목표 위치 자체가 이동합니다.
- 어깨 각도도 최대 `240도/초`로 따로 제한됩니다.
- 따라서 입력 목표가 즉시 바뀌는 방식과 실제 부품이 물리적으로 늦게 따라오는 현상을 구분할 수 없습니다.

전환 후 비교 기준:

- 마우스 목표점은 입력을 받은 틱에 즉시 바뀌어야 합니다.
- 실제 손과 발만 질량, 관절 힘, 충돌 때문에 늦게 따라와야 합니다.
